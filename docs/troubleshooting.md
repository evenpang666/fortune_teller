# 故障排查

[返回项目首页](../README.md) · [文档目录](README.md)

## 环境与依赖安装

### 找不到 Node.js 或版本不符合要求

项目要求 Node.js ≥22.13。在新终端运行 `node --version` 和 `npm --version`，确认安装已加入 PATH。Windows 安装后需要重新打开终端；Linux 可以使用 `bash start.sh`，无需依赖脚本的可执行权限。

### npm 安装失败

首次启动需要能访问 npm registry。先检查安装终端输出中的网络、代理或权限错误，然后在项目根目录手动执行：

```bash
npm ci --omit=dev
```

安装成功后重新启动。开发测试依赖不属于运行时依赖，运行测试前需执行不带 `--omit=dev` 的 `npm ci`。

### SQLite ExperimentalWarning

Node.js 22 可能对内置 SQLite 打印实验性功能提示。单独出现该提示不代表启动失败；继续检查终端是否打印网页地址。如出现实际 SQLite 错误，检查数据目录是否可写。

## 启动与访问

### 浏览器没有自动打开

保持服务运行，手动打开 `http://localhost:3210`，打开即可使用，无需登录。如果已修改端口，请使用终端打印的新地址。无桌面环境可直接用 `--no-open` 启动。

### 端口已被占用

终端通常会提示端口占用。先确认是否已运行过独立服务，或 DSH 插件正在启动同一个端口；选择一种运行方式。

独立模式在 `.env` 中修改 `PORT` 后重启。插件模式修改 `config.port` 并同步调整 Web 入口旁的端口输入框。两种模式的配置路径不同，详见[环境与配置](configuration.md)。

### 更新后仍显示旧登录页面

新版本已取消访问口令。本机与局域网设备直接打开地址即可使用。如果仍看到旧登录页面，请重启观象服务并刷新浏览器，必要时强制刷新。历史记录和 DeepSeek 配置会保留。

## 局域网访问

### 本机正常，但手机无法打开

依次检查：

1. 手机和服务端是否在同一局域网，路由器是否开启访客网络或客户端隔离。
2. 手机是否使用终端打印的服务端局域网 IP。手机上的 `localhost` 指向手机自身。
3. 独立模式 `HOST` 或插件 `config.host` 是否为 `0.0.0.0`。
4. 服务是否仍在运行，地址中的端口是否正确。
5. 操作系统防火墙是否允许可信局域网访问该 TCP 端口。

若服务端 IP 改变，请使用重启后打印的新地址。不需要关闭整个防火墙，允许指定应用或端口即可。

### 提示不支持的访问地址或来源不匹配

服务会核验 Host 和 Origin。请使用 `localhost` 或服务端本机 IP 访问；当前实现没有自定义域名与反向代理来源配置。直接将服务接入自定义域名/HTTPS 代理，可能被现有检查拒绝，需相应扩展来源校验逻辑。

## DeepSeek 分析

| 提示或现象 | 检查与处理 |
| --- | --- |
| 尚未配置 API Key | 在「设置与连接」保存密钥，或配置服务端 `DEEPSEEK_API_KEY` |
| API Key 无效 | 核实密钥是否完整；如有环境变量密钥，应修改该变量而不是只改网页密钥 |
| 余额不足 | 检查 DeepSeek 账户可用余额 |
| 请求过于频繁 | 等待后再试；本地服务也限制最多三条并发分析 |
| 超时或无法连接 | 检查服务端到 `https://api.deepseek.com` 的连通性；浏览器可上网不代表服务进程的网络正常 |
| 模型不能在网页切换 | `DEEPSEEK_MODEL` 会固定模型，移除变量并重启后可恢复网页选择 |
| 没有 token 或费用明细 | 供应商未返回可用 usage 时会显示未知，不估造用量 |
| 费用与平台账单不同 | 网页使用可配置单价估算，不自动识别节假日或价格时段；按实际账户账单核对 |

请求失败会保留盘面，可以在历史记录中重试，无需重新抽牌或起卦。重试会发起新的 API 请求；失败或超时请求也可能已产生费用，但本地未取得其用量。缓存与计费行为见[数据管理](data.md)和[费用说明](billing.md)。

## 历史与插件入口

### 切换运行模式后历史不见了

独立模式与 DSH 插件默认使用不同数据目录。确认 `FORTUNE_DATA_DIR` / `config.dataDir` 指向原数据目录，或按[数据管理](data.md)备份后迁移。不要同时运行两个服务对同一数据库进行分析。

### DSH 中没有工作室入口

确认安装到了 `web` profile，并检查插件加载错误、是否启用，以及是否存在端口冲突。必要时重启 Harness。当前验证范围为真实 Cordis/Skill 服务和独立 Web 应用；完整宿主安装及 Client 入口尚待实机验证，版本差异需结合 Harness 日志排查。具体接口与版本见 [DSH 接入指南](harness.md)。
