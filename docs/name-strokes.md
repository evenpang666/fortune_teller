# 姓名与康熙笔画自动查询

[返回项目首页](../README.md) · [文档目录](README.md)

## 使用方式

在「姓名」模式分别填写姓氏与名字，页面自动查询每个字的康熙笔画，并填入笔画栏。支持姓与名各一至二个汉字，包括复姓。自动模式可以直接点击「解析姓名」，不需要手填笔画。

例如：

| 输入 | 自动查询笔画 |
| --- | --- |
| 王 / 知远 | 王 4、知 8、远（遠）17 |
| 刘 / 清 | 刘（劉）15、清 12 |
| 欧阳 / 修 | 欧（歐）15、阳（陽）17、修 10 |

页面提供「重新自动查询笔画」按钮；勾选「手动核实 / 调整笔画」后，可以编辑姓氏和名字的笔画数组，按字序用逗号分隔。

## 查询口径与来源

使用固定版本 `shunshi-kangxi-core@0.1.1` 的离线字表，采用该表的**姓名学康熙笔画**字段。数据由第三方整理，按 MIT 许可发布；来源和简繁处理说明见[上游项目](https://github.com/shunshi-ai/kangxi-mcp/blob/main/README.zh-CN.md)。

查询在本地服务中完成，不发送姓名给字典网站、不调用 DeepSeek，也不创建历史记录。只有点击「解析姓名」才保存盘面，点击 AI 解读才按既有流程调用 DeepSeek。

姓名学康熙笔画与现代简体字形的书写笔画不同。页面显示使用的繁体字形，结果记录保存字表版本、逐字查询信息和实际采用的笔画，方便核对。

## 未收录与字形差异

未收录的字以「待核实」显示，笔画栏对应位置显示 `?`。简繁字形的字表笔画有差异时，也会提示待核实并展示候选值，不默认选择其中一个。

例如上游数据中「于 / 於」对应 3 / 8，「万 / 萬」对应 15 / 13。它们可能涉及不同字形、姓名用字或数据口径，程序不会自行合并。请核实实际姓名用字后，切换手动模式并补全每字笔画。

自动模式存在待核实字时不生成五格。手动模式仍检查笔画为 1–64 的整数，且每个字对应一个数；结果标明笔画来自用户手动核实或调整。

字表查询不能保证所有生僻字或各流派笔画口径都一致，手动调整入口始终保留。已保存的旧记录继续使用原笔画，不因字典功能更新而重新计算。

## 更新与接口

Windows/Linux 启动脚本会在字典依赖缺失时自动安装。使用 npm 命令启动的环境，可先运行 `npm ci`，再重启服务。

`POST /api/name-strokes` 接收 `{ surname, given }`，返回逐字笔画、状态、候选值及来源；查询本身不写入历史。

`POST /api/readings` 的姓名输入可使用 `strokeMode: "auto"`（默认无笔画数组时自动查询）或 `strokeMode: "manual"`。手动模式需要 `surnameStrokes` 和 `givenStrokes`；自动模式由服务端重新查询，不信任浏览器提供的笔画数组。旧调用提供数组但未指定模式时，兼容按手动模式处理。
