## DSH 模型配置

API Key、服务地址、模型提供方和默认模型均在 DSH Web 的模型设置中维护。观象使用宿主 `llm.stream()`，无需再配置自己的 Key。DSH 通过其凭据服务或启动环境解析凭据，观象不会将凭据返回浏览器。

在 DSH 修改默认模型后，下一次解读生效；已有解读仍保留原模型与用量。观象设置页只维护费用估算单价。

## 启动器变量

项目根目录 `.env` 会在启动时加载，参考 `.env.example`。

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `DSH_WEB_URL` | `http://127.0.0.1:3080` | 检查并复用此本机 DSH Web，或在此端口启动 |
| `DSH_WEB_PORT` | `3080` | 未指定 URL 时的端口 |
| `DSH_HOME` | `~/.dsh` | 复用现有 DSH profile、设置和凭据目录 |
| `DSH_CLI` / `DSH_BIN` | 自动发现 | 指定已有 DSH 的 `lib/bin.js`，沿用漫游 / 薄书的入口配置 |
| `FORTUNE_PORT` | `3100` | 独立页面首选端口，占用时自动换用空闲端口 |
| `FORTUNE_DATA_DIR` | 项目 `.data/` | 历史数据库与观象费用配置目录 |

页面默认独立监听 `0.0.0.0:3100`，本机访问 `http://127.0.0.1:3100/`，局域网设备访问 `http://主机局域网IP:实际端口/`，无需登录。首选端口由 `FORTUNE_PORT` 或插件 `config.port` 设置；端口占用时直接使用系统分配的空闲端口，启动器与页面显示实际地址。DSH 的模型和凭据继续复用，管理页认证保留，旧 DSH 子路径仅作兼容入口。

## 浏览器与代理提示

项目启动器始终向 DSH 传递 `--no-open`，让宿主不打开管理页；启动器等待观象健康检查通过后，自动打开独立端口页面。新启动与复用已有服务都采用此行为。使用 `sh start.sh --no-open` 可关闭观象页面的自动打开。

页面默认独立监听 `0.0.0.0:3100`，本机访问 `http://127.0.0.1:3100/`，局域网设备访问 `http://主机局域网IP:实际端口/`，无需登录。首选端口由 `FORTUNE_PORT` 或插件 `config.port` 设置；端口占用时直接使用系统分配的空闲端口，启动器与页面显示实际地址。DSH 的模型和凭据继续复用，管理页认证保留，旧 DSH 子路径仅作兼容入口。

启动入口和 DSH 子进程仅过滤 `UNDICI-EHPA` 这条代理实验性 warning。HTTP/HTTPS 代理、`NO_PROXY`、其他 Node 选项及其他错误和警告均保留，不修改全局 Node 或 DSH 设置。

## 环境检查与已有 DSH 复用

`sh start.sh`、`bash start.sh` / `start.bat` 优先使用当前可用 Node，必要时才使用项目内 Node。可自动补齐 Node.js ≥22.13，使用 Node 官方下载和 SHA-256 校验，安装到 `.data/node/`。系统原有 Node 保留。仅执行 `npm start` 时，Node 必须事先可用。

项目依赖按 `package-lock.json` 同步，并检查 Node 版本变化和依赖是否缺失。DSH 首先查找 PATH 和已有共享入口，再检查最低版本 0.2.0-rc.2。缺失或过低时，在 `$DSH_HOME/runtimes/web/versions/0.2.0-rc.2` 暂存安装、校验后切换；四个项目共用，失败保留原安装。DSH 版本变化后自动重新注册 Web 插件，成功才写入版本记录。符合要求时不查询 npm，也不降级新版。已有旧进程需要重启以加载新版；旧 `FORTUNE_AUTO_UPDATE` 开关不影响最低版本检查。

pnpm 根据共享 profile 的 `node_modules/.modules.yaml` / `packageManager` 选择兼容版本，并沿用已有 `storeDir`。PATH 中旧 pnpm 不匹配时会继续寻找已有的匹配版本，只有确实缺失时才补齐指定版本，不强制降到 pnpm 10，也不修改全局 pnpm 配置或重建共享 `node_modules`。缺失组件与依赖修复需要网络。

启动器以 `link:` 安装当前目录到 DSH `web` profile；因此请保留项目路径。自动识别默认端口及进程命令行 `--port` 指定的其他 DSH 服务；配置文件设置的自定义端口请显式填写 `DSH_WEB_URL`。检测到已有 DSH 时只复用，不停止原进程，不重复启动。新增插件若尚未激活，会显示启用或重启原服务的提示。

旧版 `.data/config.json` 中的 Key 不会用于插件生成；请在 DSH 中管理凭据。原有历史数据库保持可读。
